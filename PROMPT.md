# Authoring Spec — Chips Guide

This file describes how the guide is written and built, so that new chapters and later edits stay consistent with the rest of the site and with the other guides in the family (same theme, same components, different accent). It is not published on the site.

## Audience and voice

- Reader: an ML practitioner who trains, quantizes and serves models and wants the hardware reasons behind those choices. Fluent in Python/PyTorch; no electrical-engineering background assumed.
- Build every idea from first principles, then tie it back to a model-optimization decision ("Why This Matters for Model Optimization").
- Plain, direct prose. Numbers over adjectives. Say what a figure is (dense or sparse, per chip or per board, peak or measured) every time.

## Accuracy rules

1. **Dense throughput only.** Never quote a 2:4-sparse figure as if it were dense. H100 = 989 TFLOP/s BF16 dense, 1,979 FP8 dense. If a vendor only publishes a sparse number, halve it and say so.
2. **Per chip, not per board or pod.** TPU numbers are per chip; say so.
3. **Re-run code.** Every printed output in a code block must be what the code prints. If the code needs a GPU or a library that is not available, run an equivalent NumPy version and say that you did.
4. **Date-stamp fast-moving facts.** Roadmaps, prices, export rules and market share carry a year ("as of late 2026"). Announced-but-not-shipping hardware is marked *announced* or *ramping*.
5. **Primary sources first.** Vendor whitepapers, datasheets, standards (JEDEC, OCP, PCI-SIG, UCIe), and peer-reviewed papers. Every chapter ends with a References table.
6. **One data file.** Accelerator specs live in `assets/data/accelerators.json` (with a `source` URL per chip). The atlas, the roofline and fit labs, and `memory_wall.svg` all read it; update it rather than hard-coding numbers in two places.

## Components (all styled in `assets/css/style.css`)

| Component | Markup | Use for |
|---|---|---|
| Callouts | `<div class="callout note|warn|field|myth|ponder">` + `<span class="callout-title">` | Asides; `ponder` = one open question per chapter |
| Self-check | `<details class="check"><summary>Q</summary><p>A</p></details>` | Check Yourself |
| Diagrams | `.diagram` + `.diagram-grid`, `.flow`, `.flow-h`, `.compare`, `.layer-stack`, `.timeline` | Concept maps |
| Datasheet | `.datasheet` > `.ds-head` (`.ds-part`, `.ds-name`, `.ds-stamp ok|soon`, `.ds-sub`) + `.ds-grid` of tables (`td.v` for values) + `.ds-foot` | One chip's spec card |
| Die floorplan | `.die-wrap` > `.die-frame` > `.die` of `.blk` (compute, tensor, cache, mem, io, ctrl, npu, gpu, cpu, media), `.hbm-col` | What is on the silicon |
| Cross-section | `.xsec` > `.xs-row` of `.xs` (die, dram, bump, tsv, interposer, bridge, substrate, board, optic, heat, gap) | Packaging stacks |
| Spec bars | `.specbars` > `.sb-row` (`.sb-name`, `.sb-track i[style=--v:NN]`, `.sb-val`, `.sb-note`) | Comparing one number across chips |
| Stats | `.stats` > `.stat` (`.stat-num` with `<em>` accent, `.stat-label`) | Headline numbers |
| Receipts | `.receipts` > `.receipt` (`.r-head`, `.r-sub`, `.r-rule`, `.r-line[.muted|.hl]`, `.r-total`, `.r-foot`, `.r-barcode`) | Itemized costs: energy, memory, money |
| HBM budget | `.budget` > `.bg-row` (`.bg-name`, `.bg-track[style=--cap]` of `i.w|i.kv|i.ws[style=--v]`, `.bg-note`) | Stacked capacity |
| Bitfields | `.bitfield` strips | Number formats |
| Labs | `<div class="lab" data-lab="NAME"><noscript>…</noscript></div>` | roofline, bits, fit, systolic, wafer, sparsity, quant, cache, atlas |
| Flowcharts | `<!-- flowchart:NAME -->` … `<!-- /flowchart:NAME -->` | Generated SVG; never edit between the markers |
| Figures | `<figure class="figure"><img src="./assets/images/X.svg" …><figcaption>` | Generated by `tools/make_figures.py` |

Jekyll/kramdown gotchas:
- Raw HTML blocks must not contain blank lines.
- `jekyll-relative-links` rewrites `.md` links in Markdown but **not** inside raw HTML: use `.html` in HTML `href`s.
- Markdown emphasis does not render inside HTML blocks; use `<em>` / `<strong>`.
- Wrap code containing `{{` or `{%` in `{% raw %}` … `{% endraw %}`.

## Generated artefacts and checks

```bash
python3 tools/build_flowcharts.py          # inject SVG flowcharts (add --check in CI)
python3 tools/make_figures.py              # regenerate assets/images/*.svg (add --check in CI)
node tools/test_labs.js                    # pure-function tests behind every lab
```

To add a flowchart: define it in `CHARTS` in `tools/build_flowcharts.py` with `N(...)` nodes and `E(...)` edges, put the two markers in the chapter, run the script, and screenshot the page to check for overlapping labels.

To add a lab: write the pure function in `assets/js/chips-labs.js` (exported for Node), add tests to `tools/test_labs.js`, register the renderer in `LABS`, and drop the `div.lab` into the chapter and `labs.md`.

## Theme

Dark family theme with the **copper** accent `#e8916a` (dim `#c06c43`). Sidebar navigation is grouped by Part (`url: ""` entries in `_config.yml` render as section headers); the layout adds a reading-progress bar, a chapter eyebrow, prev/next pager, copy buttons on code and a `/`-to-focus chapter filter.
